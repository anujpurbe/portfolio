I've gone through a lot of "generic developer portfolio" templates. They all share the same shape: *Name → About → Skills → Projects → Contact*, with percentage skill bars and a picture of a laptop.

I don't want that. This site is my chance to demonstrate frontend engineering the way my [DSA work](/projects/dsa-algorithms) demonstrates the fundamentals: deliberately, and with evidence.

## What I'm doing differently

- **DSA-first identity.** My hero isn't a decorative 3D shape — it's `PROBLEM → ALGORITHM → CODE → DATA → RESULT`, the pipeline I actually think in.
- **No invented numbers.** Skill bars, inflated stats, fake "years of experience" — all cut. If I haven't proven a skill in real work, it's not on the list.
- **Honest data states.** GitHub stats come live from the API, and if the API fails the site says *"data unavailable"* instead of showing a stale screenshot of better times.
- **An engineering log.** This journal is what keeps the site alive between project launches. One MDX file per entry, a new one roughly every two weeks, each one cross-linked to the project it's actually about.

## Stack

Next.js App Router, TypeScript, Tailwind CSS, Motion, MDX. Nothing exotic — the point is that the build quality is the pitch, not the libraries.

## What's next

- Getting the two real projects documented properly — Hiingers and this portfolio already have full write-ups on their [project pages](/projects).
- Starting the backend + system design deep-dive.
- Keeping this log honest: the [engineering log](/journal) section records the real commits and the real dates.

If you're reading this from the site, you're already looking at the deliverable — the journal is the changelog of everything you see here.
